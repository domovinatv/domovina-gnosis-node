# Istraživanje: macOS 24/7 operacije (2026-10-01)

> Sirovi nalaz istraživačkog agenta. Činjenice su provjerene na dan pisanja; stavke označene *unverified* treba potvrditi na samom MacBooku.

I checked current Apple man pages locally and current vendor docs online. Two findings change the plan:

- **Homebrew 7.0.0 (13 Sep 2026)** moved Intel macOS to Tier 3. It no longer builds new Intel bottles, and Homebrew stops running on Intel Macs on 1 Sep 2027. Expect `brew install` to compile from source.
- **macOS 26 Background Task Management (BTM)** can silently block LaunchDaemons whose executables are not signed by an Apple Developer ID.

The man pages came from this workstation, which runs macOS 26.5.1 on **arm64**, not from the Intel target. Run the `sysctl` and `pmset -g cap` checks on the MacBook itself.

## 1. launchd

**Use LaunchDaemons with `UserName`.** LaunchAgents only load when a user logs in. A plist in `/Library/LaunchDaemons` loads at boot. `UserName` and `GroupName` "only apply to services loaded into the privileged system domain" (`man launchd.plist`). Install each plist as `root:wheel` with mode `644`, or launchd refuses to load it.

**Commands** (`man launchctl`):
```bash
sudo launchctl bootstrap system /Library/LaunchDaemons/hr.domovina.nethermind.plist
sudo launchctl bootout   system/hr.domovina.nethermind      # stop + unload (honours ExitTimeOut)
sudo launchctl kickstart -k system/hr.domovina.nethermind   # restart (-k kills running instance)
sudo launchctl print     system/hr.domovina.nethermind      # state, last exit status, limits
sudo launchctl enable    system/hr.domovina.nethermind      # persists across boots
```

**Keys** (all verified in `man launchd.plist` unless marked otherwise):
- **`KeepAlive`:** `{SuccessfulExit=false}` restarts the job when it exits non-zero, and it implies `RunAtLoad`. `{Crashed=true}` restarts it after a crash signal (SIGSEGV etc.). For a node, `{SuccessfulExit=false}` is enough.
- **`ThrottleInterval`:** the default is 10 s between spawns. Use 30 to avoid tight crash loops.
- **`ExitTimeOut`:** the time between SIGTERM and SIGKILL. The man page only says "system-defined". The common figure is 20 s ([launchd.info](https://www.launchd.info/), [launchd-dev list](https://launchd-dev.macosforge.narkive.com/AKXf7q5W/about-the-exittimeout-key-in-a-daemon-s-configuration-plist)). `0` means infinite, and Apple says not to use it. Set `180`.
  - **Unverified:** whether a full system shutdown honours long `ExitTimeOut` values. Before any planned reboot, run `bootout` on the validator, then the CL, then Nethermind.
- **`ProcessType`:** if you leave it unset, the job gets "light resource limits… throttling its CPU usage and I/O bandwidth". Use **`Standard`** (or `Interactive`). Never use `Background`.
- **`LowPriorityIO`:** leave it unset or `false` for Nethermind. It is fine for the Node.js listener.
- **`NumberOfFiles`** under `SoftResourceLimits` / `HardResourceLimits`:
  - **Gotcha:** in a system daemon this key also sets the sysctl `kern.maxfiles` (Soft) or `kern.maxfilesperproc` (Hard), not just `setrlimit`. A value set too low lowers the limit for the whole system.
  - The defaults observed on 26.5 were `kern.maxfiles=184320`, `kern.maxfilesperproc=92160`, and `launchctl limit maxfiles` showing 256 soft / unlimited hard. A daemon without these keys therefore gets a soft limit of 256, which is too low for RocksDB.
  - Set Soft and Hard to the same value, for example 524288.
- **`WorkingDirectory`, `EnvironmentVariables`, `StandardOutPath`, `StandardErrorPath`** work as you would expect.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>hr.domovina.nethermind</string>
  <key>UserName</key><string>gnosis</string>
  <key>ProgramArguments</key><array>
    <string>/opt/gnosis/nethermind/nethermind</string>
    <string>--config</string><string>gnosis</string>
    <string>--data-dir</string><string>/opt/gnosis/data/nethermind</string>
  </array>
  <key>WorkingDirectory</key><string>/opt/gnosis/nethermind</string>
  <key>EnvironmentVariables</key><dict><key>DOTNET_gcServer</key><string>1</string></dict>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><dict><key>SuccessfulExit</key><false/></dict>
  <key>ThrottleInterval</key><integer>30</integer>
  <key>ExitTimeOut</key><integer>180</integer>
  <key>ProcessType</key><string>Standard</string>
  <key>SoftResourceLimits</key><dict><key>NumberOfFiles</key><integer>524288</integer></dict>
  <key>HardResourceLimits</key><dict><key>NumberOfFiles</key><integer>524288</integer></dict>
  <key>StandardOutPath</key><string>/dev/null</string>
  <key>StandardErrorPath</key><string>/opt/gnosis/logs/nethermind.stderr.log</string>
</dict></plist>
```
The `DOTNET_gcServer` variable is only an example and is optional.

**macOS 15/26 gotchas:**
- **Login Items notification:** BTM shows an "Allow in the Background" notification for each new daemon. Manage these in System Settings → General → Login Items & Extensions ([Apple](https://support.apple.com/guide/deployment/manage-login-items-background-tasks-mac-depdca572563/web)).
- **Silent blocking:** since macOS 14.6.1, BTM gates LaunchDaemons whose executables lack an Apple Developer signature. On Tahoe it blocks daemons that run a shell script (`/bin/sh`) ([write-up](https://mgaebler.me/en/blog/nix-macos-tahoe-btm-blocks-launchdaemons/); third-party, but consistent with Apple's docs).
  - Point `ProgramArguments` directly at the binaries, not at wrapper scripts.
  - Check with `sudo sfltool dumpbtm | grep -A8 hr.domovina`. If you see `disallowed`, toggle the item in "Allow in the Background".
  - **Test with a real reboot,** because a manual `bootstrap` can work until the next boot and then fail.
- **Privacy protections:** do not put data or logs in `~/Documents`, `~/Desktop`, or external volumes without granting Full Disk Access (`man launchd.plist` CAVEATS). Use `/opt/gnosis` or `/usr/local/gnosis`.

## 2. FileVault and unattended reboot

- **`fdesetup authrestart [-delayminutes N]`** reboots once and skips the pre-boot unlock. The man page warns that "FileVault protections are reduced": an unlock key is stored in RAM and, on supported systems, in the SMC until the next boot. On T2 Macs this is handled by the Secure Enclave rather than the SMC ([Jamf community](https://community.jamf.com/general-discussions-2/filevault-2-and-remote-access-33705) / [Der Flounder](https://derflounder.wordpress.com/2012/09/22/fdesetup-authrestart-filevault-2s-one-time-encryption-bypass-feature/); not Apple docs). Check support with `fdesetup supportsauthrestart`.
- authrestart only covers that one planned reboot. A power loss, kernel panic or crash reboot still stops at the unlock screen ([Macworld](https://www.macworld.com/article/2568036/how-to-manage-filevault-to-maintain-remote-access-to-your-mac.html)).
- **T2 specifics:** the internal SSD is always hardware-encrypted by the T2. With FileVault off, the key is not tied to your password, so the data is protected only while the disk is out of the machine, not against someone holding the Mac itself.
- **Recommendation:** keep FileVault on, because the machine holds validator keys and sits in an office. Use authrestart for planned reboots. Accept that unplanned reboots need someone on site (or ARD/VNC is also blocked at pre-boot). Slashing risk is low, since a validator that is offline only loses its rewards. As defence in depth, keep the keystores encrypted and the password file `0600`, owned by the service user.

## 3. Power (`man pmset`)

```bash
sudo pmset -a sleep 0 displaysleep 10 disksleep 0 powernap 0 standby 0 autopoweroff 0 hibernatemode 0 tcpkeepalive 1 womp 1 ttyskeepawake 1
sudo pmset -a autorestartatconnect 1   # if `pmset -g cap` lists it (unverified on 2019 MBP)
pmset -g; pmset -g cap; pmset -g assertions
```
- **`autorestart`** ("restart on power loss") is a desktop feature and does not appear on MacBooks ([Apple Community](https://discussions.apple.com/thread/255887539)). The battery acts as a UPS. If it drains completely, use `autorestartatconnect` if it exists, or open the lid. Intel MBPs from 2016 on boot when the lid opens or power is connected (unverified on 26).
- **`hibernatemode`:** the default is 3 on laptops. Set it to 0 together with `standby 0` and `autopoweroff 0` so that no hibernation image is written.
- **Leave the lid open.** Clamshell mode needs an external display.
- **`caffeinate`** is an alternative: `caffeinate -dimsu` held by its own LaunchDaemon. `pmset` is simpler and persists.
- **Software update:** `sudo softwareupdate --schedule off`, plus:
  ```bash
  sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate AutomaticDownload -bool false
  sudo defaults write /Library/Preferences/com.apple.SoftwareUpdate AutomaticallyInstallMacOSUpdates -bool false
  sudo defaults write /Library/Preferences/com.apple.commerce AutoUpdate -bool false
  ```
  These still exist, but whether Tahoe honours them is **unverified** ([Apple Community thread](https://discussions.apple.com/thread/256145255)). Also turn off "Install macOS updates" in System Settings → General → Software Update → Automatic Updates (ⓘ). Keeping Security Responses on is reasonable, but they can restart the Mac.

## 4. Battery on a 24/7 charger

- **Battery health management** ("Manage battery longevity") is on by default for Intel Macs with Thunderbolt 3 ([Apple 102588](https://support.apple.com/en-us/102588)). It lowers maximum charge based on temperature and charging history, but it does not set a hard cap.
- **Optimized Battery Charging** (Big Sur and later) learns your routine and delays charging past 80% ([Apple 102338](https://support.apple.com/en-us/102338)).
- **The fixed Charge Limit in System Settings needs macOS 26.4 and Apple silicon,** so it is not available on this Intel machine.
- **AlDente:** the developers say it supports macOS 26, and recent releases fixed Tahoe issues (Sailing Mode, "Stop charging when app closed"). There is an open issue about an Intel 16" MBP on 26.4.1 not charging while asleep ([#1756](https://github.com/AppHouseKitchen/AlDente-Battery_Care_and_Monitoring/issues/1756)), which does not matter if the Mac never sleeps.
  - The free version has the charge limiter. Pro adds Sailing Mode, Heat Protection and similar features (from memory; check the current tier split).
  - AlDente is a GUI login app, so it needs a logged-in session.
- **`bclm`** ([zackelia/bclm](https://github.com/zackelia/bclm)) "does not work on macOS ≥ 15.0 due to new entitlement enforcement… without disabling SIP", so it is out.
- **Swelling:** sitting at 100% while warm is the main cause of ageing and swelling, and an i9 under sync load runs hot.
  - Cap the charge around 75–80% with AlDente.
  - Keep the Mac on a stand with airflow.
  - Check `system_profiler SPPowerDataType` (Condition, Cycle Count) every month.
  - Retire the machine if the trackpad starts to bulge.

## 5. Log rotation

newsyslog (`man newsyslog.conf`) has five required fields: `logfile [owner:group] mode count size(KB) when flags [pidfile] [sig]`. The flags used here:
- `N`: no process to signal
- `J`: bzip2 (or `Z` for gzip)
- `C`: create the file if missing (with `-C`)
- `G`: glob

**Gotcha:** newsyslog renames the file and has no copy-and-truncate option. launchd keeps the `StandardOutPath` file descriptor open, so after rotation the process keeps writing into the rotated file. So:
- Prefer each client's own rotation:
  - **Nethermind:** NLog file target `archiveAboveSize` / `maxArchiveFiles` in `NLog.config` ([NLog wiki](https://github.com/nlog/NLog/wiki/File-target)). Nethermind's default values are unverified, so check the shipped `NLog.config`.
  - **Lighthouse:** `--logfile-max-size` (default 200 MB) and `--logfile-max-number` (default 5) ([Lighthouse CLI](https://lighthouse-book.sigmaprime.io/help_general.html)).
- Send stdout to `/dev/null` and keep only stderr in a file, so it stays small.
- For that small file, a size-only rotation with `N` is acceptable. Alternatively, use the Node.js listener's own logger (pino or rotating-file-stream).

`/etc/newsyslog.d/gnosis.conf`:
```
# logfilename                          [owner:group]  mode count size  when flags
/opt/gnosis/logs/nethermind.stderr.log  gnosis:staff   640  5     50000 *    NJ
/opt/gnosis/logs/listener.log           gnosis:staff   640  7     20000 *    NJ
```
Test with `sudo newsyslog -nvv` (dry run).

## 6. Exposing RPC without inbound ports: Cloudflare Tunnel

- **WebSockets:** "Yes. Cloudflare Tunnel has full support for Websockets" ([Tunnel FAQ](https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/)). They need Universal SSL and an SSL mode of Flexible, Full or Full (strict) ([common errors](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/troubleshoot-tunnels/common-errors/)).
- **Install:** `sudo cloudflared service install` creates a LaunchDaemon at `/Library/LaunchDaemons/com.cloudflare.cloudflared.plist`. It reads `/etc/cloudflared/config.yml` and logs to `/Library/Logs/com.cloudflare.cloudflared.{out,err}.log`. Without sudo it becomes a LaunchAgent, which you do not want ([macOS service docs](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/as-a-service/macos/)).
  - Because of the Homebrew Tier 3 change, prefer the official darwin-amd64 binary from the [downloads page](https://developers.cloudflare.com/tunnel/downloads/) over `brew`.
  - The Go binary is unsigned for BTM purposes (unverified), so check `sfltool dumpbtm`.

`/etc/cloudflared/config.yml` (format from the [config-file docs](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/configuration-file/)):
```yaml
tunnel: <TUNNEL-UUID>
credentials-file: /etc/cloudflared/<TUNNEL-UUID>.json
ingress:
  - hostname: rpc-origin.example.hr
    service: http://127.0.0.1:8545
  - hostname: ws-origin.example.hr
    service: http://127.0.0.1:8546     # WS upgrade passes through http:// service
  - service: http_status:404
```

**Protection:**
- Put an Access application on the `*-origin` hostnames, with a Service Auth policy that accepts a service token.
- Callers send the `CF-Access-Client-Id` and `CF-Access-Client-Secret` headers, or a single configurable header ([service tokens](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/)). Since 26 Aug 2026, new secrets use the `cfast_…` format.
- **Do not ship the service token in a mobile app,** because it can be extracted.

**Recommendation: never expose raw RPC.** Put a Worker on a public hostname (`rpc.example.hr`) and have it:
1. Allow only an explicit list of methods (`eth_call`, `eth_getLogs` with a block-range cap, `eth_blockNumber`, `eth_getBalance`, `eth_subscribe` limited to `newHeads`/`logs`, and so on). Reject `admin_*`, `debug_*`, `txpool_*`, `personal_*`, `engine_*` and batch requests above N.
2. Rate-limit per IP or per app key with the [Workers Rate Limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) (not fetched this session).
3. Forward to the Access-protected origin hostname, adding the service-token headers from Worker secrets.
4. Proxy WebSockets frame by frame so that each message can be filtered.

Also keep Nethermind's `JsonRpc.EnabledModules` minimal (`Eth,Net,Web3,Subscribe`), and never put the Engine API (8551) behind the tunnel.

## 7. Firewall, P2P ports, UPnP

- Gnosis uses EL 30303 TCP/UDP and CL 9000 TCP/UDP ([Gnosis docs](https://docs.gnosischain.com/node/manual/configure-server)). Lighthouse also uses 9001/UDP for QUIC since v4.5 ([Lighthouse networking](https://lighthouse-book.sigmaprime.io/advanced_networking.html)).
- **Without forwarding,** the node only makes outbound connections. It still syncs and attests, but peer discovery is weaker, peers turn over more, and it can only connect to peers that have open ports.
  - Nethermind's default target is about 50 peers on Gnosis and Lighthouse's is about 100. Expect fewer and more fluctuation, especially on the CL ([Gnosis low-peer issue](https://github.com/sigp/lighthouse/issues/4490)).
  - This is workable for a single validator.
- **UPnP:** Nethermind has `Network.EnableUPnP`, default **false** ([Nethermind config](https://docs.nethermind.io/1.28.0/fundamentals/configuration/)). Lighthouse's UPnP is **on** by default and maps ports if the router allows it ([Lighthouse book](https://lighthouse-book.sigmaprime.io/advanced_networking.html)). Since you want no inbound ports, add `--disable-upnp`.
- **Application firewall:** `socketfilterfw` only affects inbound connections. Its stealth mode plus blocking unsigned apps can kill peer ports, but without port forwarding that does not matter.
  ```bash
  sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate on --setstealthmode on
  ```
  Bind RPC and metrics to `127.0.0.1`.

## 8. Building Rust on Intel macOS 26

- Since Rust 1.90, `x86_64-apple-darwin` is **Tier 2 with host tools**. It is still built and distributed through rustup, but automated tests are no longer guaranteed, so expect bugs to pile up over time ([Rust blog](https://blog.rust-lang.org/2025/08/19/demoting-x86-64-apple-darwin-to-tier-2-with-host-tools)).
- Homebrew 7.0.0: Intel is "Tier 3; no new bottles", and Homebrew stops running on Intel on 1 Sep 2027. It suggests MacPorts ([brew.sh](https://brew.sh/2026/09/13/homebrew-7.0.0/)).
  - `brew install cmake protobuf` will probably build from source, which is slow but works.
  - Better: use the official binaries (cmake.org .dmg, protoc release zip from GitHub) or MacPorts.
- Setup: `xcode-select --install`, then rustup. Pin the toolchain with `rust-toolchain.toml`.
- Prefer prebuilt Lighthouse x86_64-apple-darwin release binaries if they are still published (**unverified for current versions**). Nethermind ships osx-x64 builds, also to be checked per release.

## 9. Time sync

- macOS uses `timed`, which syncs against `time.apple.com` and is configured in `/etc/ntp.conf` ([Eclectic Light](https://eclecticlight.co/2025/05/21/system-time-clocks-and-their-syncing-in-macos/)).
- `MAXIMUM_GOSSIP_CLOCK_DISPARITY` is 500 ms, and in practice you want under about 100–200 ms ([analysis](https://hackmd.io/@ericsson49/BJfLjEX-8)).
- `timed` is usually within tens of milliseconds, but there are reports of a steady ~200 ms offset, and it is not designed for tight discipline. **It is probably adequate but unverified.**
- **Monitor it:** run `sntp time.cloudflare.com` from a cron or launchd job and alert above 100 ms. Lighthouse also logs clock-skew warnings.
- If it drifts, install chrony (MacPorts or source), which takes over from `timed`.

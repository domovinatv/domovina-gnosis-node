# Istraživanje: EL/CL klijenti na Intel macOS (2026-10-01)

> Sirovi nalaz istraživačkog agenta, provjeren preko GitHub API-ja i `nethermind --help` iz 2.0.0 zipa.

I've verified all five questions against primary sources. The main findings: use Nethermind 2.0.0 as the execution client, and Teku is the easiest good consensus client on Intel macOS. There are two traps. Lighthouse built from source won't run Gnosis unless the `gnosis` build feature is enabled. And Nethermind 2.0's default database can't resume an interrupted first sync, which matters on a laptop.

## 1. Execution client: Nethermind 2.0.0

**Still the right choice?** Yes. Gnosis docs list four execution clients: Nethermind, Erigon, Reth and Geth ([docs.gnosischain.com/node](https://docs.gnosischain.com/node/)). Nethermind and Lighthouse together hold a majority client share on Gnosis, and the Fusaka announcement asks operators to consider minority clients ([validategnosis blog](https://blog.validategnosis.com/p/gnosis-chain-fusaka-hard-fork-announcement)). For the execution client that is a diversity concern, not a reason to avoid it.

**Executable name (verified by downloading and unzipping `nethermind-2.0.0-bec830cd-macos-x64.zip`):**
- The top level holds `nethermind` (a single-file Mach-O x86_64 binary, 270 MB), `NLog.config`, `configs/`, `plugins/`, `Data/` and `keystore/`. There is no `Nethermind.Runner`.
- `configs/gnosis.json` ships in the zip, so `--config gnosis` works.
- That config sets `SecondsPerSlot: 5`, `EnginePort: 8551`, `PivotNumber: 48330000`, and ancient bodies/receipts barriers at 25349537.

**GPG:** every zip has a `.asc`. The key is `AD12 7976 5093 C675 9CD8 A400 24A7 7461 6F1E 617E` ("Nethermind <devops@nethermind.io>"), as stated in the [2.0.0 release notes](https://github.com/NethermindEth/nethermind/releases/tag/2.0.0).
- keys.openpgp.org returned no data for it; keyserver.ubuntu.com worked.
- `gpg --verify` on the macOS x64 zip gave **Good signature**:
  ```
  gpg --keyserver hkps://keyserver.ubuntu.com --recv-keys AD1279765093C6759CD8A40024A774616F1E617E
  gpg --verify nethermind-2.0.0-bec830cd-macos-x64.zip.asc nethermind-2.0.0-bec830cd-macos-x64.zip
  ```

**2.0.0 breaking changes that affect us** ([release notes](https://github.com/NethermindEth/nethermind/releases/tag/2.0.0)):
- **The new "flat" state database is now the default** for fresh syncs (`FlatDb.Enabled=true`). It has known issues:
  - **Snap sync on flat cannot resume across a restart.** A restart wipes the progress and starts again (#13601). On a MacBook this means: no sleep or reboot during the first sync (run it under `caffeinate -dimsu`), or sync on the older backend with `--FlatDb.Enabled=false`, which can resume.
  - Copy-style full pruning doesn't run on flat.
  - Never set `FlatDb.Enabled=false` on a datadir that already has a flat database; it silently wipes and resyncs.
- `Db.FlushOnExit` changed from a boolean to an enum. Negative numbers in config now stop the node from starting.
- `Blocks.PreWarmStateOnBlockProcessing` was renamed to `Blocks.PreWarming`.
- `Receipt.MaxBlockDepth` default dropped to 1000, which limits `eth_getLogs` ranges.
- Fresh nodes serve snap data by default. The notes give `Sync.SnapServingEnabled=false` to turn it off, but that key is **not in the 2.0.0 `--help` output** (unverified).
- **Unverified:** whether `Pruning.CacheMb` still does anything on the flat backend, which has its own `FlatDb.*` cache keys.

**Recommended command:**
```
./nethermind -c gnosis -dd ~/gnosis/nethermind \
  --JsonRpc.Enabled true --JsonRpc.Host 127.0.0.1 --JsonRpc.Port 8545 \
  --Init.WebSocketsEnabled true --JsonRpc.WebSocketsPort 8546 \
  --JsonRpc.EngineHost 127.0.0.1 --JsonRpc.EnginePort 8551 \
  --JsonRpc.JwtSecretFile ~/gnosis/jwt.hex \
  --JsonRpc.EnabledModules "[eth,net,web3,subscribe,health]" \
  --HealthChecks.Enabled true \
  --Metrics.Enabled false --Metrics.ExposeHost 127.0.0.1 --Metrics.ExposePort 6060 \
  --Network.P2PPort 30303 --Network.DiscoveryPort 30303 \
  [--FlatDb.Enabled=false   # only if you want a resumable first sync]
```
The `--Metrics.Expose*` flags are optional. `--Metrics.Enabled` controls pushing to a Pushgateway, not the scrape endpoint.

**Disk:**
- Nethermind's docs give a Gnosis total of **509 GB**: state 66, receipts 218, blocks 202, headers 11, bloom 9.4 ([docs.nethermind.io/fundamentals/database](https://docs.nethermind.io/fundamentals/database)). That figure is undated and probably comes from the older backend.
- The 2.0 notes measure a full flat Gnosis *archive* at 941 GB.
- A pruned node fits on 1 TB alongside the consensus client, but with limited headroom.
- Official Nethermind minimum for Gnosis: 16 GB RAM, 2 cores, macOS 13+ ([system requirements](https://docs.nethermind.io/get-started/system-requirements)).

**Sync time:** no official figure exists. My estimate is several hours for state plus up to about a day for old bodies and receipts on NVMe.

## 2. Consensus client on Intel macOS

Latest releases, checked via the GitHub API on 2026-10-01:

| Client | Latest | macOS x86_64 binary? | Gnosis |
|---|---|---|---|
| Lighthouse | v8.2.3 (v8.3.0-rc.0 today) | **No.** Dropped in v8.0.0 ([PR #7862](https://github.com/sigp/lighthouse/pull/7862)) after Rust demoted x86 macOS | Only with the `gnosis` build feature |
| Nimbus | v26.9.1 | **No.** Only macOS arm64 | Needs a separate build, `make gnosis-build`, producing `build/nimbus_beacon_node_gnosis` (from the [Makefile](https://github.com/status-im/nimbus-eth2/blob/stable/Makefile)) |
| Teku | 26.9.1 (2026-09-28) | **Platform-independent Java tarball/zip** with `.sha256` | `--network=gnosis`, with a Gnosis docs page |
| Lodestar | v1.49.0 | No. Linux only; source build needs Node LTS v24 + pnpm | `--network gnosis` |

**Lighthouse from source:**
- Requirements: Rust ≥ **1.88** (MSRV in `lighthouse/Cargo.toml`), `brew install cmake protobuf`, and Xcode command-line tools.
- The [Lighthouse book](https://lighthouse-book.sigmaprime.io/installation_source.html) quotes about 10 minutes to build; a SIGKILL during the build means out of memory.
- **Critical:** `make` builds with the default features only. `main.rs` exits with "Eth spec `gnosis` is not supported by this build" unless built with `--features gnosis`. Correct build:
  ```
  git clone https://github.com/sigp/lighthouse && cd lighthouse && git checkout v8.2.3
  FEATURES=gnosis,slasher-lmdb,beacon-node-leveldb make
  ```
  The `slasher-lmdb,beacon-node-leveldb` part keeps the default features, because setting `FEATURES` replaces them.
- The Homebrew `lighthouse` formula builds with `--no-default-features` and no `gnosis`, and has no Intel macOS bottle. **It can't run Gnosis.**

**Teku (recommended):**
- No compiler needed, not one of the two majority clients, has a built-in validator client, and has had native Gnosis support for a long time ([Gnosis Teku docs](https://docs.gnosischain.com/node/manual/beacon/teku)).
- **Requires Java 25+** ([Teku install docs](https://docs.teku.consensys.io/get-started/install/install-binaries)). Temurin 25.0.4 for macOS x64 is available from Adoptium.
- The Homebrew `teku` formula has no Intel macOS bottle either, so use the tarball:
  ```
  curl -LO https://github.com/Consensys/teku/releases/download/26.9.1/teku-26.9.1.tar.gz
  shasum -a 256 teku-26.9.1.tar.gz   # expect 2510817b1ad128e62eef79129dba13158d750f584a1191424d616862e59d523f
  ```
- Run command:
  ```
  teku --network=gnosis --data-base-path=~/gnosis/teku \
    --checkpoint-sync-url=https://checkpoint.gnosischain.com \
    --ee-endpoint=http://127.0.0.1:8551 --ee-jwt-secret-file=~/gnosis/jwt.hex \
    --rest-api-enabled=true --rest-api-interface=127.0.0.1 --rest-api-port=5052 \
    --p2p-port=9000 --p2p-peer-upper-bound=100 \
    --validators-proposer-default-fee-recipient=0x0000000000000000000000000000000000000000 \
    --metrics-enabled=true --metrics-interface=127.0.0.1 --metrics-port=8008
  ```
  The fee recipient is a placeholder. On a 64 GB machine, set the Teku heap with `JAVA_OPTS=-Xmx8g` (my suggestion, not an official figure).

**Lighthouse equivalent** (if you build it with gnosis):
```
lighthouse bn --network gnosis --datadir ~/gnosis/lighthouse \
  --checkpoint-sync-url https://checkpoint.gnosischain.com \
  --execution-endpoint http://127.0.0.1:8551 --execution-jwt ~/gnosis/jwt.hex \
  --http --http-address 127.0.0.1 --http-port 5052 \
  --port 9000 --target-peers 100 --suggested-fee-recipient 0x…
```

## 4. Gnosis network facts
Source: [gnosischain/configs mainnet/config.yaml](https://github.com/gnosischain/configs/blob/main/mainnet/config.yaml).

- 5 s slots, 16 slots per epoch (80 s per epoch). Deposit contract `0x0B98…45d9`.
- Pectra (Electra): epoch 1337856, 2025-04-30 14:03:40 UTC.
- **Fusaka (Fulu): epoch 1714688, 2026-04-14 12:06:20 UTC.** Minimum versions at the time: Nethermind 1.36.2, Lighthouse v8.1.3, Teku 26.4.0, Nimbus v26.3.1, Lodestar v1.41.1. Lighthouse v7.1.0 is therefore unusable.
- **No Gloas/Glamsterdam fork is scheduled for Gnosis.** It isn't in the config repo (last fork-related commit 2026-03-20), and Gnosis's own hard-fork page lists nothing after Pectra and is stale (updated Nov 2025). Ethereum Glamsterdam hits Sepolia on 2026-10-06; its mainnet date is still to be decided.
- Official hardware: at least 4 threads, at least 16 GB RAM, NVMe preferred; disk space is the main bottleneck. Upload is about 700 MB/hour ([docs](https://docs.gnosischain.com/node/)).
- Ports:
  - Execution client: 30303 TCP and UDP.
  - Consensus client: 9000 TCP and UDP. Lighthouse also uses 9001 UDP (QUIC); that is from memory, not re-checked.
  - Keep 8545, 8546, 8551 and 5052 on localhost only.

## 5. Erigon instead?
No, for this machine:
- Erigon v3.7.0 ships **Linux binaries only**. Building it needs Go ≥ 1.26 and a C++ toolchain ([Erigon docs](https://docs.erigon.tech/get-started/installation)).
- Its built-in consensus client, Caplin, could replace a separate one, and it would help execution-client diversity.
- But a self-compiled Go build on a platform with no shipped binaries carries more risk than Nethermind's signed, officially shipped x64 macOS binary.
- I found no Gnosis disk figure for Erigon (unverified).
